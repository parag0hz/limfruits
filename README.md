# 임과일 (limfruits)

과일 농가 직판 온라인 쇼핑몰입니다. 전남 나주 농장에서 직접 재배한 과일(첫 상품은 나주배)을 회원가입 없이 주문하고, 토스페이먼츠로 결제하고, 관리자(부모님)가 휴대폰으로 상품과 주문을 관리할 수 있습니다. 스마트스토어처럼 **홈에서 상품을 먼저 고르고, 상세페이지에서 옵션을 골라 구매**하는 구조입니다.

- 손님: 홈 상품 목록에서 상품 선택 → 상세페이지에서 옵션·수량 선택 → 주문서 작성 → 토스 결제 → 주문번호로 배송 조회
- 관리자: 비밀번호 하나로 로그인 → 신규 주문 확인 → 운송장 입력(발송 처리) → 필요 시 결제취소 → 상품 추가/사진 등록, 가격·품절 관리

**스택**: Next.js 16 (App Router) · TypeScript · Tailwind CSS v4 · 토스페이먼츠 결제위젯 v2 · Supabase(선택) · jose(관리자 세션)

## 로컬 실행 — 데모 모드

DB도, 결제 키도 없이 바로 전체 흐름을 볼 수 있습니다.

```bash
npm install
npm run dev
```

http://localhost:3000 을 열면:

- **데이터**: 환경변수가 없으면 자동으로 **인메모리 데모 모드**로 동작합니다. 상품 3개(나주배·황금배·도라지배즙)와 옵션 13개, 예시 주문 2개(이름에 "(예시)" 표기)가 미리 들어 있습니다. 서버를 재시작하면 데모 데이터는 초기화됩니다. 리뷰도 등록해 볼 수 있지만, 데모 모드에는 사진 저장소가 없어 **리뷰 사진은 저장되지 않습니다**(후기 글만 등록됨).
- **결제**: 토스페이먼츠 **공개 테스트 키**가 기본 내장되어 있어 결제창까지 실제로 열립니다. 테스트 키라 실제 돈은 빠져나가지 않습니다.
- **관리자**: 홈 푸터의 "관리자" 링크 또는 `/admin` 접속 → 기본 비밀번호는 **`limfruits`** 입니다. (환경변수 `ADMIN_PASSWORD`를 설정하면 그 값으로 바뀝니다.) 이 기본값은 `npm run dev` 개발 모드에서만 동작하며, 배포(프로덕션)에서는 `ADMIN_PASSWORD`와 `AUTH_SECRET`을 설정하지 않으면 안전을 위해 관리자 로그인이 아예 막힙니다.

환경변수를 쓰려면 `.env.example`을 `.env.local`로 복사해 채우면 됩니다.

## Supabase 실제 연동 (주문을 영구 저장)

데모 모드는 서버가 재시작되면 주문이 사라지므로, 실제 판매 전에 Supabase를 연결하세요.

1. https://supabase.com 에서 가입 후 **새 프로젝트 생성** (무료 플랜으로 충분)
2. 프로젝트 대시보드 → **SQL Editor** → 이 저장소의 `supabase/schema.sql` 내용 전체를 붙여넣고 **Run** (테이블 6개 + 시드 상품 3개·옵션 13개가 만들어집니다)
3. 대시보드 → **Settings → API** 에서 값 2개를 복사해 `.env.local`(또는 Vercel 환경변수)에 넣기:

```
SUPABASE_URL=https://xxxx.supabase.co        # Project URL
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...      # service_role 키 (secret)
```

- `SUPABASE_SERVICE_ROLE_KEY`는 **서버 전용 비밀 키**입니다. 절대 `NEXT_PUBLIC_` 접두사를 붙이거나 외부에 공개하지 마세요.
- 두 값이 모두 있으면 자동으로 Supabase 모드로 전환되고, 없으면 데모 모드로 동작합니다 (`lib/db.ts`).
- 테이블은 RLS(행 수준 보안)를 켜고 정책을 만들지 않아, 서비스 롤 키로만 접근할 수 있습니다.

**구매 후기(reviews) 테이블 — 이미 Supabase를 쓰고 있던 경우**

- v2.2부터 구매 후기 기능이 추가되어 `reviews` 테이블이 필요합니다. **기존에 schema.sql을 이미 실행했던 프로젝트라면**, `supabase/schema.sql` 맨 아래 **"v2.2 리뷰"** 절(해당 주석부터 파일 끝까지)만 복사해 SQL Editor에서 실행하면 됩니다. 모든 문장이 멱등이라 전체 파일을 다시 실행해도 안전합니다 (기존 데이터는 바뀌지 않음).
- 리뷰 사진은 Supabase **Storage의 `reviews` 공개 버킷**에 저장됩니다. 버킷은 첫 사진 업로드 때 자동으로 만들어지므로 따로 만들 필요가 없습니다.

**선물·대량 주문(orders) 컬럼 — 이미 Supabase를 쓰고 있던 경우**

- v2.4부터 선물·대량 주문(다중 배송지) 기능이 추가되어 `orders` 테이블에 `kind`(단일/선물 구분)와 `shipments`(받는 분별 배송 건) 컬럼이 필요합니다. **기존에 schema.sql을 이미 실행했던 프로젝트라면**, 아래 두 문장만 SQL Editor에서 실행하면 됩니다 (멱등이라 여러 번 실행해도 안전, 기존 주문은 자동으로 `SINGLE`로 채워집니다):

```sql
alter table public.orders
  add column if not exists kind text not null default 'SINGLE';
alter table public.orders
  add column if not exists shipments jsonb not null default '[]';
```

- 전체 `supabase/schema.sql`을 다시 실행해도 같은 결과가 됩니다 (모든 문장이 멱등, 기존 데이터는 바뀌지 않음).

**입장 팝업(site_settings) 테이블 — 이미 Supabase를 쓰고 있던 경우**

- v2.6부터 입장 팝업(명절 발송 안내)이 추가되어 사이트 설정을 저장할 `site_settings` 테이블이 필요합니다. **기존에 schema.sql을 이미 실행했던 프로젝트라면**, 아래 세 문장만 SQL Editor에서 실행하면 됩니다 (멱등이라 여러 번 실행해도 안전):

```sql
create table if not exists public.site_settings (
  key text primary key,
  value jsonb not null default '{}'
);
alter table public.site_settings enable row level security;
```

- 테이블이 아직 없어도 사이트는 정상 동작합니다 — 팝업은 꺼진 상태(기본값)로 취급되어 손님 화면에 나타나지 않습니다. 위 SQL을 실행한 뒤에야 관리자 "팝업" 화면에서 켜고 날짜를 저장할 수 있습니다. 전체 `supabase/schema.sql`을 다시 실행해도 같은 결과가 됩니다.

**회원(users) 테이블 · orders.user_id 컬럼 — 이미 Supabase를 쓰고 있던 경우**

- v2.8부터 카카오 소셜 로그인(회원 마이페이지)이 추가되어 회원을 담을 `users` 테이블과, 주문을 회원과 잇는 `orders.user_id` 컬럼이 필요합니다. **기존에 schema.sql을 이미 실행했던 프로젝트라면**, 아래 문장만 SQL Editor에서 실행하면 됩니다 (모두 멱등이라 여러 번 실행해도 안전, 기존 주문의 `user_id`는 `null`(비회원)로 남습니다):

```sql
create table if not exists public.users (
  id uuid primary key default gen_random_uuid(),
  kakao_id text unique not null,
  nickname text not null default '',
  created_at timestamptz not null default now()
);
alter table public.users enable row level security;

alter table public.orders
  add column if not exists user_id text;
create index if not exists orders_user_id_idx on public.orders (user_id);
```

- 이 테이블·컬럼이 없어도 **비회원 주문과 주문조회는 그대로 동작**합니다. 카카오 키(`KAKAO_REST_API_KEY`)를 넣지 않으면 로그인 버튼 자체가 나타나지 않으므로, 로그인 기능을 켜기 전이라면 위 SQL을 미리 실행하지 않아도 됩니다. 전체 `supabase/schema.sql`을 다시 실행해도 같은 결과가 됩니다.

## 토스페이먼츠 실 연동 (실제 결제 받기)

기본 내장된 키는 **누구나 쓰는 문서용 테스트 키**라 실제 정산이 되지 않습니다. 실제로 돈을 받으려면:

1. https://developers.tosspayments.com 에서 회원가입 → **내 상점의 테스트 키**(클라이언트 키 `test_ck_…` / 시크릿 키 `test_sk_…`)를 발급받아 환경변수로 설정하고 결제 흐름을 확인
2. 토스페이먼츠에 **상점(사업자) 심사**를 신청 — 사업자등록증, 통신판매업 신고 등이 필요합니다
3. 심사 승인 후 **라이브 키**(`live_ck_…` / `live_sk_…`)로 교체:

```
NEXT_PUBLIC_TOSS_CLIENT_KEY=live_ck_...   # 브라우저에서 쓰는 클라이언트 키
TOSS_SECRET_KEY=live_sk_...               # 서버 전용 시크릿 키 (절대 공개 금지)
```

- 결제 금액은 항상 **서버가 DB 가격으로 다시 계산**해 승인하므로, 브라우저에서 금액을 조작할 수 없습니다.
- **결제 취소(환불)** 는 관리자 페이지의 주문 상세에서 "결제취소" 버튼을 누르면 토스 취소 API가 호출되어 자동 환불됩니다. 토스 **상점관리자 콘솔**(https://app.tosspayments.com)에서도 직접 취소할 수 있습니다 (이 경우 사이트의 주문 상태도 관리자 페이지에서 '취소'로 맞춰 주세요).

## Vercel 배포

1. 이 프로젝트를 GitHub 저장소에 푸시
2. https://vercel.com 에서 가입 → **Add New → Project** → GitHub 저장소 선택 (Next.js는 설정 없이 자동 인식)
3. **Settings → Environment Variables** 에 아래 값들을 등록하고 다시 배포:

| 변수 | 설명 |
|---|---|
| `SUPABASE_URL` | Supabase 프로젝트 URL |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase service_role 키 (secret) |
| `NEXT_PUBLIC_TOSS_CLIENT_KEY` | 토스 클라이언트 키 |
| `TOSS_SECRET_KEY` | 토스 시크릿 키 |
| `ADMIN_PASSWORD` | 관리자 비밀번호 (**반드시 설정** — 프로덕션에서 미설정이면 관리자 로그인이 거부됩니다) |
| `AUTH_SECRET` | 관리자·회원 세션 서명 키 (32자 이상 아무 랜덤 문자열, **반드시 설정** — 미설정이면 관리자 기능이 동작하지 않습니다. 카카오 로그인 세션도 이 값으로 서명합니다) |
| `NEXT_PUBLIC_SITE_URL` | 배포 주소 (예: `https://limfruits.vercel.app`) — 카톡 공유 미리보기(OG 이미지)·카카오 로그인 redirect_uri 계산에 사용 |
| `KAKAO_REST_API_KEY` | (선택) 카카오 로그인용 REST API 키. 넣으면 회원 로그인·마이페이지가 켜지고, 없으면 로그인 버튼이 나타나지 않습니다 (아래 "카카오 로그인(회원)" 참고) |
| `KAKAO_CLIENT_SECRET` | (선택) 카카오 앱에서 Client Secret 사용을 켠 경우에만 |

- 이후에는 GitHub에 푸시할 때마다 자동으로 재배포됩니다.
- 도메인을 사려면 Vercel의 **Domains** 메뉴에서 연결할 수 있습니다.

## 신규 주문 문자 알림 (4시간마다)

새 주문이 몇 건 들어왔는지 판매자 휴대폰으로 문자를 보내는 기능입니다. 주문이 0건이면 문자를 보내지 않습니다.

1. **문자 발송 계정** — [알리고](https://smartsms.aligo.in) 가입(사업자 인증) 후 **발신번호 등록**, API 키 발급. 건당 약 9원이라 월 1,000~2,000원 수준입니다.
2. **Vercel 환경변수** 추가 후 Redeploy:
   - `CRON_SECRET` — 아무 긴 랜덤 문자열 (아래 3번과 같은 값)
   - `ALIGO_API_KEY` / `ALIGO_USER_ID` / `ALIGO_SENDER`(등록한 발신번호)
   - `NOTIFY_PHONE` — 문자 받을 번호 (미설정 시 010-2618-5151)
   - (선택) `NOTIFY_WINDOW_HOURS` 주기 시간(기본 4), `NOTIFY_ALWAYS=1` 0건도 발송
3. **스케줄 등록** — [supabase/cron.sql](./supabase/cron.sql)의 `<CRON_SECRET>`을 2번과 같은 값으로 바꿔 Supabase SQL Editor에서 실행. 4시간마다 자동 호출됩니다.

알리고 키를 넣기 전에는 문자 대신 서버 로그에만 기록되는 드라이런 모드로 동작하므로, 순서 상관없이 설정해도 안전합니다.

## AI 상담 챗봇

사이트 우측 하단에 뜨는 상담 챗봇입니다. 단순 FAQ가 아니라 상품·가격·품절은 DB를 실시간으로 조회해 답하고, 주문 상태는 주문번호와 전화번호를 확인한 뒤 안내합니다 (주소 등 개인정보는 답변에 포함하지 않습니다).

**켜는 방법** — API 키 하나만 넣으면 됩니다.

1. https://console.anthropic.com 에서 가입 후 **API Keys** 메뉴에서 키(`sk-ant-...`)를 발급받습니다. 선불 크레딧 충전이 필요합니다.
2. 발급받은 키를 환경변수로 설정하고 재배포합니다:

```
ANTHROPIC_API_KEY=sk-ant-...   # 서버 전용 비밀 키 (절대 공개 금지)
```

- 로컬은 `.env.local`, 배포는 Vercel **Settings → Environment Variables** 에 넣으면 됩니다.
- **키가 없으면 챗봇 버튼 자체가 화면에 나타나지 않습니다.** 사이트의 다른 기능은 평소대로 동작하므로, 키 없이 운영해도 문제없습니다. 키를 넣는 순간 활성화됩니다.

**선택 환경변수**

| 변수 | 기본값 | 설명 |
|---|---|---|
| `CHAT_MODEL` | `claude-opus-5` | 사용할 Claude 모델. 비용을 줄이려면 `claude-haiku-4-5`로 교체 |
| `CHAT_EFFORT` | `low` | 응답 속도·품질 조절 (`low`/`medium`/`high`). 상담 챗은 지연이 중요해 기본 `low` |

**비용 안내** — 사용한 만큼만 과금됩니다 (100만 토큰 기준, 미화):

| 모델 | 입력 | 출력 | 비고 |
|---|---|---|---|
| `claude-opus-5` (기본) | $5 | $25 | 답변 품질이 가장 좋음 |
| `claude-haiku-4-5` | $1 | $5 | 가장 저렴, 간단한 상담에 충분 |

상담 1회는 보통 수천 토큰 수준이라 일반적인 문의량에서는 월 몇 달러 이내입니다. IP당 10분에 20회 요청 제한이 걸려 있어 악의적 사용으로 비용이 급증하는 것을 막습니다. 정확한 사용량은 console.anthropic.com의 Usage 메뉴에서 확인할 수 있습니다.

## 카카오 로그인(회원)

손님이 카카오 계정으로 로그인하면 **마이페이지(`/my`)에서 내 주문 내역과 배송 현황을 한곳에서** 볼 수 있습니다. 로그인은 **편의 기능**일 뿐이라, **로그인 없이도 주문·결제·주문조회는 그대로** 됩니다(비회원 주문 유지). 포인트·쿠폰 같은 적립 기능은 아직 없습니다.

**키가 없으면 로그인 버튼 자체가 나타나지 않습니다** — 챗봇과 같은 안전모드입니다. `KAKAO_REST_API_KEY`를 넣는 순간 헤더에 "로그인", 로그인한 손님에게는 "마이페이지"가 켜집니다. 키 없이 운영해도 사이트의 다른 기능은 평소대로 동작합니다.

**켜는 방법**

1. https://developers.kakao.com 에서 로그인 → **내 애플리케이션 → 애플리케이션 추가하기**로 앱을 만듭니다(앱 이름·회사명은 자유).
2. 만든 앱 → **앱 설정 → 앱 키**에서 **REST API 키**를 복사합니다. 이 값이 `KAKAO_REST_API_KEY` 입니다.
3. **제품 설정 → 카카오 로그인**을 **활성화 ON** 으로 켜고, 같은 화면에서 **Redirect URI**에 아래 주소를 **정확히** 등록합니다(배포 주소 기준):

   ```
   https://limfruits.vercel.app/api/auth/kakao/callback
   ```

   - 실제 도메인을 쓰면 그 도메인으로 등록하세요. 로컬 개발에서 로그인까지 테스트하려면 `http://localhost:3000/api/auth/kakao/callback`도 함께 등록합니다.
   - 이 값은 사이트가 `NEXT_PUBLIC_SITE_URL`을 기준으로 만들므로, **`NEXT_PUBLIC_SITE_URL`을 실제 주소로 설정**해 두어야 등록한 Redirect URI와 정확히 일치합니다(미설정 시 요청 주소에서 유추).
4. **제품 설정 → 카카오 로그인 → 동의 항목**에서 **닉네임**(profile_nickname)을 사용 설정합니다(마이페이지 인사말에 사용).
5. (선택) 보안을 강화하려면 **제품 설정 → 카카오 로그인 → 보안**에서 **Client Secret**을 발급·사용으로 켜고, 그 값을 `KAKAO_CLIENT_SECRET`로 설정합니다. 켜지 않았다면 이 변수는 넣지 않아도 됩니다.
6. Vercel **Settings → Environment Variables** 에 `KAKAO_REST_API_KEY`(와 필요 시 `KAKAO_CLIENT_SECRET`)를 넣고 재배포합니다. `AUTH_SECRET`(로그인 세션 서명)과 `NEXT_PUBLIC_SITE_URL`도 설정돼 있어야 합니다.

**Supabase 연동 시** — 회원을 저장하려면 `users` 테이블과 `orders.user_id` 컬럼이 필요합니다. 위 **"Supabase 실제 연동"**의 *회원(users) 테이블 · orders.user_id 컬럼* 항목 SQL을 실행하세요(신규 설치는 `schema.sql`에 이미 포함). 데모(인메모리) 모드에서도 로그인 흐름은 동작하지만 서버를 재시작하면 회원 정보가 초기화됩니다.

**동작·보안 메모**

- 회원 세션은 관리자 세션과 **쿠키 이름·서명 claim이 완전히 분리**되어 있어 서로 섞이지 않습니다. 카카오 액세스 토큰은 서버에서 회원 정보를 한 번 읽는 데만 쓰고 클라이언트·DB에 저장하지 않습니다.
- 로그인은 CSRF(state) 검증을 거치고, 로그인 후 이동은 **내부 경로로만** 제한됩니다(오픈 리다이렉트 방지). 마이페이지는 **본인 주문만** 보여 줍니다(로그인으로 인증되므로 전화번호 재확인 없음). 로그인 전에 비회원으로 넣은 주문은 마이페이지에 자동으로 붙지 않으며, 주문번호+연락처로 **주문조회**에서 확인할 수 있습니다.

## 관리자 페이지 사용법 (부모님용 안내)

휴대폰 브라우저로 쓰시는 것을 기준으로 만들었습니다. 홈 화면에 바로가기를 추가해 두면 편합니다.

**1. 로그인**
- 사이트 맨 아래 "관리자"를 누르거나 주소 뒤에 `/admin`을 붙여 접속합니다.
- 비밀번호를 입력하면 7일 동안 로그인이 유지됩니다.

**2. 새 주문 확인**
- 로그인하면 바로 **주문 목록**이 뜨고, "신규주문" 탭에 결제까지 끝난 주문이 모입니다. 빨간 숫자가 확인 안 한 신규 주문 개수입니다.
- 새 주문이 왔는지 보려면 오른쪽 위 **새로고침**을 누릅니다.
- 주문 카드를 누르면 상세 화면이 열립니다. 손님 이름 옆 **전화 버튼**을 누르면 바로 전화가 걸리고, **주소 복사**를 누르면 택배 접수할 때 붙여넣을 수 있습니다.

**3. 발송 처리 (운송장 입력)**
- 배를 보내고 나서 주문 상세에서 **택배사 선택 → 운송장 번호 입력 → "발송 처리"** 를 누릅니다.
- 주문 상태가 "배송중"으로 바뀌고, 손님도 주문조회에서 운송장 번호를 볼 수 있게 됩니다.
- 배송이 끝나면 **"배송완료 처리"** 를 눌러 정리합니다.

**3-1. 주문이 많을 때 — 로젠 송장 일괄 출력 (명절용)**
주문 목록의 "신규주문" 탭에 **"송장 출력 (로젠택배)"** 상자가 있습니다. 주문을 한 건씩 처리하지 않고 한꺼번에 처리하는 방법입니다.
1. **"1. 신규주문 엑셀 받기"** 를 누르면 신규 주문 전체(받는분·주소·품목)가 엑셀 파일로 저장됩니다.
2. 이 엑셀을 로젠택배 계약고객 시스템(**iSales**)의 대량 등록에 올려 송장을 한꺼번에 출력합니다. (iSales 양식에 맞춰 열을 옮겨 붙여야 할 수 있습니다)
3. iSales에서 나온 **주문번호·운송장번호가 담긴 엑셀**을 **"2. 운송장 엑셀 올리기"** 로 올리면, 해당 주문들이 자동으로 운송장 저장 + "배송중" 처리됩니다. (파일 첫 행에 "주문번호"(또는 "배송건번호"), "운송장번호" 제목만 있으면 됩니다)

**3-2. 선물·대량 주문 (다중 배송지)**
명절에 한 사람(보내는 분)이 여러 받는 분에게 한 번에 결제하고, 받는 분마다 다른 구성을 보내는 주문입니다.
- **손님 쪽**: 홈이나 상품 상세의 **"선물·대량 주문"** 링크(`/order/gift`)로 들어가 받는 분을 한 명씩 추가하거나, **엑셀 양식**(받는분성명·전화번호·우편번호·주소·상세주소·상품옵션·수량·선물메시지)을 내려받아 명단을 채워 한 번에 올린 뒤 결제합니다. 금액은 각 세트 가격(배송비 포함가)을 서버가 다시 합산하므로 조작되지 않습니다.
- **관리자 쪽**: 주문 목록에서 선물 주문은 카드에 **"선물 N건"** 배지와 "받는 분 홍길동 외 N명"으로 표시됩니다. 주문 상세를 열면 **보내는 분 정보** 아래에 **배송 건이 받는 분별로 나뉘어** 보이고, 각 건마다 전화 버튼·주소 복사·구성·선물 메시지가 있습니다. 건마다 **택배사 선택 → 운송장 입력 → 저장**을 하고, **모든 배송 건에 운송장을 채운 뒤** 맨 아래 **"전체 발송 처리"** 를 누르면 주문이 "배송중"이 됩니다.
- **엑셀 일괄 처리도 그대로 됩니다**: 3-1의 "신규주문 엑셀 받기"에서 선물 주문은 **배송 건마다 한 줄**로 나오고, 각 줄의 **배송건번호**가 `주문번호#1`, `주문번호#2` … 형태입니다. 로젠 iSales에서 송장을 출력한 뒤 그 배송건번호와 운송장번호가 담긴 엑셀을 "운송장 엑셀 올리기"로 올리면 **건별로 운송장이 저장**되고, 한 주문의 모든 배송 건이 채워지면 자동으로 "배송중"으로 바뀝니다.

**4. 주문 취소 (환불)**
- 주문 상세 맨 아래 **"결제취소"** → 취소 사유 입력 → **"취소 확정"**.
- 결제된 주문이면 손님께 자동으로 환불됩니다. 되돌릴 수 없으니 확인 창을 잘 읽고 눌러 주세요.

**5. 상품 추가 (새 과일 팔기 시작할 때)**
- 위쪽 **"상품 관리"** 탭 → **"+ 상품 추가"** 를 누르고 상품 이름(예: 사과)만 입력하면 상품이 만들어지고 바로 편집 화면이 열립니다.
- 편집 화면에서 **한 줄 소개**와 **상세 소개**(손님이 상세페이지에서 읽는 글)를 적고 **"저장"** 을 누릅니다.
- **판매 옵션**(무게·구성별 가격)을 하나 이상 추가해야 손님이 주문할 수 있습니다. "+ 옵션 추가"에서 이름(예: 가정용 3kg)과 가격을 넣으면 됩니다.
- 준비가 다 되면 맨 위 토글을 **"보이게 하기"** 로 바꿔야 손님 화면에 나타납니다.

**6. 상품 사진 넣기**
- 상품 편집 화면의 **"대표 사진 주소"** 칸에 사진의 인터넷 주소(URL)를 붙여넣고 **"저장"** 을 누릅니다. 붙여넣으면 바로 아래에 미리보기가 나오니 사진이 맞는지 확인하세요.
- 사진 주소 만드는 쉬운 방법: 무료 이미지 올리기 사이트(예: https://imgbb.com)에 휴대폰 사진을 올리면 주소가 나옵니다. 그 주소를 복사해 붙여넣으면 됩니다.
- 비워 두면 임과일 로고 그림이 대신 표시됩니다.

**7. 상세페이지 꾸미기 (블록)**
- 손님이 상세페이지에서 보는 소개 화면을 **블록(카드)** 을 쌓아 만들 수 있습니다. 상품 편집 화면 아래쪽 **"상세페이지 구성"** 에서 합니다.
- **"+ 블록 추가"** 를 누르면 블록 종류가 나옵니다 — 제목 / 문단 / 사진 / 포인트(장점을 번호와 함께 강조, 번호는 자동) / 인증 배지 / 규격 표(중량·과수 정리) / 안내 박스(포장·배송 안내). 각 칸에 적힌 회색 예시를 참고해 채우면 됩니다.
- 블록 오른쪽 **↑ ↓** 버튼으로 순서를 바꾸고, **삭제**로 지웁니다. 위에서 아래 순서 그대로 손님에게 보입니다.
- 다 만들면 꼭 **"상세페이지 저장"** 을 누르세요. 저장 전에는 손님 화면이 바뀌지 않습니다. 저장 후 **"미리보기 (새 창)"** 으로 손님이 보는 화면을 확인할 수 있습니다.
- 블록을 하나라도 만들면 5번에서 적은 "상세 소개" 글 대신 블록이 보입니다. 블록을 전부 지우면 다시 "상세 소개" 글이 보입니다.

**8. 가격 수정·품절 처리**
- 상품 편집 화면의 **판매 옵션**에서 옵션별로 이름, 설명, 가격을 고칠 수 있습니다. 고친 뒤 꼭 **"저장"** 을 눌러야 반영됩니다.
- 물량이 떨어지면 **"품절 처리하기"** 를 누르세요 (누르는 즉시 저장). 손님 화면에 바로 "품절"로 표시되고 주문이 막힙니다. 다시 팔 때는 "판매 재개하기"를 누르면 됩니다.
- 상품을 아예 안 팔 때는 편집 화면 맨 위 토글로 **"숨기기"** 를 누르면 손님 화면에서 사라집니다 (지우지 않아도 됩니다).

**9. 구매 후기 관리**
- 상품을 받은 손님은 **주문조회** 화면에서 별점·후기 글·사진(최대 3장)을 남길 수 있습니다. 주문할 때 쓴 주문번호와 전화번호가 맞아야만 쓸 수 있고, 한 주문에 후기는 하나입니다.
- 등록된 후기는 상품 상세페이지 아래 **"구매 후기"** 에 손님 이름이 가려진 채로(예: 김*원) 표시됩니다.
- 위쪽 **"리뷰"** 탭에서 전체 후기를 볼 수 있습니다. 여기서는 어떤 손님이 썼는지 실명과 주문번호가 그대로 보입니다.
- 부적절한 후기는 **"숨기기"** 를 누르면 손님 화면에서 바로 사라집니다 (후기 자체는 남아 있어 "보이게 하기"로 되돌릴 수 있습니다).
- 완전히 지우려면 **"삭제"** 를 누릅니다. 사진도 함께 지워지며, 삭제하면 되돌릴 수 없습니다.

**10. 입장 팝업 (명절 발송 안내)**
- 손님이 사이트에 처음 들어올 때 뜨는 안내 창입니다. 추석·설 선물세트의 **발송 기간을 달력으로** 보여 주고, 아래 버튼으로 선물 주문 화면으로 바로 보낼 수 있습니다. 위쪽 **"팝업"** 탭에서 설정합니다.
- **평소에는 꺼져 있습니다.** 발송 날짜가 정해지지 않았는데 잘못된 날짜가 손님에게 보이지 않도록, 기본값은 "꺼짐"입니다. 명절이 다가와 날짜를 정한 뒤에 켜세요.
- 설정 순서: ① **팝업 제목**(예: 추석 선물세트 예약 안내)과 **안내 문구**를 적고 ② **발송 시작일·마감일**(과 필요하면 예약 마감일)을 달력에서 고르고 ③ **버튼 문구**와 **버튼을 누르면 갈 곳**을 정한 다음 ④ 맨 위 **"켜기"** 로 바꾸고 ⑤ 맨 아래 **"저장"** 을 누릅니다. **저장을 눌러야** 손님 화면에 반영됩니다(켜기/끄기도 저장을 눌러야 적용됩니다).
- 화면 가운데 **미리보기**로 손님에게 보일 모습을 미리 확인할 수 있습니다. 날짜를 모두 비워 두면 달력 없이 안내 문구만 보입니다.
- 손님은 팝업 아래 **"오늘 하루 보지 않기"** 를 누르면 그날 하루 동안 다시 뜨지 않습니다. 명절이 끝나면 다시 **"팝업"** 탭에서 **"끄기" → "저장"** 으로 내려 주세요.

## 오픈 준비 (개인정보처리방침·약관·SEO)

실제 오픈과 토스페이먼츠 실결제 심사를 앞두고 갖춰야 하는 법적 문서·동의·검색 노출 관련 항목입니다.

**1. 개인정보처리방침 · 이용약관**
- 두 페이지는 각각 `/privacy`(개인정보처리방침), `/terms`(이용약관) 주소에 있습니다. 파일은 `app/(site)/privacy/page.tsx`, `app/(site)/terms/page.tsx` 입니다.
- 사이트 맨 아래 **푸터**에 두 링크가 있고, 주문/선물 결제 화면의 **필수 동의** 문구 안에서도 새 탭으로 열립니다.
- 내용은 확정 사업자 정보(상호 풍천대봉감농원 · 대표 임용균 · 사업자등록번호 412-90-42034 · 통신판매업신고 제2011-전남나주-60호 · 전남 나주시 덕룡로 33-8)와 실제 데이터 흐름(토스 결제 위탁·택배사 제공·Supabase 보관·AI 상담 국외 이전)에 맞춰 작성돼 있습니다. 시행일은 2026-08-10 입니다. **법령·상호·연락처가 바뀌면 두 파일의 하단 사업자 정보와 시행일을 갱신**하세요. (전문 검토가 필요하면 PLACEHOLDERS.md 참고)

**2. 주문 동의 체크박스 (마케팅 수신동의)**
- 주문/선물 결제 직전에 상점 동의 블록이 있습니다. **[필수]** 개인정보 수집·이용 및 약관 동의는 체크하지 않으면 결제가 진행되지 않습니다(토스 결제창 약관과는 별개).
- **[선택]** "광고성 정보(문자) 수신 동의"에 체크한 주문은 `orders.marketing_consent = true`로 저장됩니다. 나중에 명절·행사 때 **재구매 안내 문자**를 보낼 대상을 이 값으로 추립니다. 관리자 주문 엑셀/DB에서 동의한 연락처만 골라 발송에 활용하세요. (동의하지 않은 손님에게 광고 문자를 보내면 안 됩니다.)

**3. 검색 노출 (SEO)**
- `app/sitemap.ts`(→ `/sitemap.xml`)와 `app/robots.ts`(→ `/robots.txt`)가 자동 생성됩니다. 사이트맵에는 홈·활성 상품 상세·선물주문·주문조회·개인정보처리방침·약관이 들어가고, 관리자(`/admin`)·API(`/api`)·결제 결과 페이지는 크롤러에서 차단됩니다.
- 상품 상세는 상품명·설명·대표 이미지가 검색 미리보기에 뜨도록 메타데이터와 구조화 데이터(JSON-LD: Product, 가격·재고·별점은 실제 값)를 넣었고, 홈에는 판매자 정보(Organization)·사이트(WebSite) 구조화 데이터가 있습니다.
- **검색엔진 등록은 직접 하셔야 합니다(사이트가 자동으로 해 주지 않습니다):**
  - **네이버 서치어드바이저** (https://searchadvisor.naver.com) — 사이트 등록 → 소유 확인 → **요청 > 사이트맵 제출**에 `https(주소)/sitemap.xml` 입력.
  - **구글 서치 콘솔** (https://search.google.com/search-console) — 속성 추가 → 소유 확인 → **Sitemaps** 에 `sitemap.xml` 제출.
  - 소유 확인용 메타 태그를 요구하면 `app/layout.tsx`의 `metadata.verification` 또는 각 콘솔이 안내하는 HTML 파일 방식으로 넣습니다.

**4. `NEXT_PUBLIC_SITE_URL` 은 반드시 실제 주소로**
- 사이트맵·robots·구조화 데이터·카톡 공유 미리보기(OG)의 **절대 URL이 모두 이 값을 기준**으로 만들어집니다. 설정하지 않으면 `http://localhost:3000`으로 채워져 검색엔진·공유 미리보기가 깨집니다.
- Vercel **Settings → Environment Variables** 에 `NEXT_PUBLIC_SITE_URL=https://limfruits.vercel.app`(또는 실제 도메인)을 넣고 재배포하세요.

**5. 기존 Supabase 설치에 `marketing_consent` 컬럼 추가 (신규 설치는 불필요)**
- `supabase/schema.sql`을 처음부터 실행하는 신규 설치는 이미 포함돼 있습니다. **이미 운영 중인 DB**라면 Supabase 대시보드 **SQL Editor** 에서 아래 한 문장만 실행하면 됩니다(멱등 — 여러 번 실행해도 안전):

```sql
alter table public.orders
  add column if not exists marketing_consent boolean not null default false;
```
